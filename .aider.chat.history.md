SQL injection is a type of attack where an attacker injects malicious SQL code into a query to manipulate a database. This can lead to unauthorized data access, data corruption, or even complete database takeover. 

### How to Prevent SQL Injection:
1. **Use Parameterized Queries/Prepared Statements**: 
   - Separate SQL logic from user input. Use placeholders (e.g., `?` in JDBC or `@param` in PDO) instead of concatenating user input directly into SQL strings.
   - Example (Python with `sqlite3`):
     ```python
     import sqlite3
     name = "Alice"
     query = "SELECT * FROM users WHERE name = ?"
     cursor.execute(query, (name,))
     ```

2. **Input Validation and Sanitization**:
   - Validate all user inputs to ensure they match expected formats (e.g., email, phone number).
   - Escape special characters (e.g., `'`, `;`, `--`) if manual sanitization is required.

3. **Use an ORM (Object-Relational Mapper)**:
   - Frameworks like SQLAlchemy (Python) or ActiveRecord (Ruby) abstract SQL queries and automatically handle parameterization.

4. **Least Privilege Principle**:
   - Use database accounts with minimal permissions necessary for the application to function.

5. **Web Application Firewalls (WAF)**:
   - Deploy WAFs to detect and block malicious SQL patterns in incoming traffic.

6. **Regular Security Audits**:
   - Perform code reviews and penetration testing to identify vulnerabilities.

### Example of Vulnerable vs. Safe Code:
**Vulnerable (bad practice):**
```python
user_input = input("Enter name: ")
query = f"SELECT * FROM users WHERE name = '{user_input}'"
cursor.execute(query)
```

**Safe (parameterized):**
```python
user_input = input("Enter name: ")
query = "SELECT * FROM users WHERE name = ?"
cursor.execute(query, (user_input,))
```

Always prioritize parameterized queries to ensure user input is treated as data, not executable code.
