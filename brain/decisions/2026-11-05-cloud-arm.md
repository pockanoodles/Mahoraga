# ADR 2026-11-05 — The study measures the cloud side too, through one audited egress

## Status
Accepted (2026-11-05).

**Builds on:** `2026-10-29-long-term-study.md` (a study of local against cloud) and
`2026-10-02-local-audit-product.md` (the verdict is the deliverable). It changes what the
verdict's cloud side is made of, and adds the always-on OptiPlex as the machine that runs it.

## Context

Every verdict so far compares a measured local resolve rate with an assumed cloud. The cloud
price per task is the reader's spend divided by their tasks ($150 / 200 = $0.75), and the
cloud agent is assumed to solve every task it gets. Neither has been measured, so the study
measured half of "local against cloud".

agentbench drove only local agents, and on purpose: `agents.py` refused cloud models, because
a third-party agent sending code to a provider would skip the repo's single audited egress.
The Linux side had no sandbox at all. DATAFLOW.md said so.

On 2026-11-05 Kaito added a Dell OptiPlex 7070 to the tailnet (i7-9700, 16 GB single-channel
DDR4, no usable GPU). It can't run the models usefully: about 2–3 tok/s of generation and some
30 tok/s of prefill for a 9.7B Q4, estimated from its memory bandwidth, against the laptop's
14.5 and 140. A cloud agent needs no local model, though, so the OptiPlex can run it every
night without touching the laptop, whose own nights keep getting cut short by Kaito using it.
Kaito said to run it on his Northeastern Claude seat, which is the login on the OptiPlex.

## Decision

1. **A `claude:<model>` arm runs Claude Code headless on the same tasks, prompt and grader.**
   It pins a model id (claude-opus-5-5 first, since Opus is what Kaito's own Claude Code
   runs). An alias like `opus` is refused, because it moves when Anthropic ships. Each
   attempt starts with an empty HOME, so none of the user's CLAUDE.md, skills, hooks or
   memory comes along, and nothing carries from one task to the next. Auth is a token from
   `claude setup-token`. Web tools are off. The CLI's `total_cost_usd` is recorded per attempt,
   so the cloud price per task becomes a measurement.
2. **`egress.Proxy` is the cloud arm's single audited egress.** It's an HTTP CONNECT proxy
   that tunnels only to `api.anthropic.com:443` and writes every tunnel asked for, allowed or
   refused, with the bytes each way, into the attempt's log. The sandbox gives the agent no
   other way out.
3. **Linux gets a real sandbox: bubblewrap.** Every namespace is new, including the network
   one. The system is read-only. `/tmp`, `/var/tmp` and `/run` are private, so the agent can't
   reach tmux's socket and type into Kaito's sessions. The source repo and the bench are
   emptied. The only exits are loopback ports that `bridge.py` carries to Unix sockets
   outside: the proxy for the cloud arm, a relay to Ollama for a local one. Every agent on
   both platforms also loses read access to the user's credential folders, since whatever a
   cloud arm reads goes to its vendor.
4. **Sending code is a choice made at a terminal each time.** `audit run` needs
   `--allow-cloud`. The queue refuses cloud arms, so nothing unattended sends code anywhere.
5. **The isolation canary gains a network probe and runs whether or not the guard does.**
   Whether an agent can reach the answer, or the internet, is the measurement's validity,
   not the machine's health.

## Consequences

- The verdict can drop the 100%-cloud assumption. The pair on 47 tasks gives the tasks only
  local solves, the tasks only cloud solves, and a measured cloud cost per task. The verdict
  change is its own PR, written once the data exists.
- **Cross-machine grading isn't identical.** The OptiPlex mines the laptop's 47 shas from the
  same source heads. Prompts and fail-to-pass tests match exactly, but attrs has 4 fewer
  pass-to-pass tests on Linux (1229 against 1233 on the first task): 4 tests pass on macOS
  and not on Linux, so on the OptiPlex an attempt can't regress them. The pairing has to name
  this.
- The cloud arm runs on Kaito's seat, so the numbers are what that seat's Opus did, at API
  list prices. Usage limits on the seat show up as error results, which count as harness
  crashes: the attempt is retried, and three in a row drop the arm for the night.
- `ollama_net` makes local arms on Linux work under the new sandbox. They aren't run there
  yet: the OptiPlex is too slow for them.
