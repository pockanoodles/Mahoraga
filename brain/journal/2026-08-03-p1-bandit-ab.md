# 2026-08-03 — P1: bandit vs round-robin vs static vs oracle, live A/B

## Design

The "learns which model to route to" claim needed a number. Method: for each
bank, a **force-explore cross** (every arm × every prompt, fresh inference) from
which round-robin, both statics, and the per-prompt oracle are *derived exactly
at zero extra cost*, plus a **bandit-mode run** (LinUCB, cold state, seeded)
through the real `/api/task` path. Each policy ran under its own scratch `HOME`
(everything — bandit state, stores, decision log — is hardcoded to
`~/.mahoraga-v2`, and `observe()` trains even on pinned-arm rows, so isolation
is the only way to keep baselines from contaminating the learner). Grading:
execution-verified pass@1 via `verify_replay.run_case` — the only cross-policy
honest metric. Infra failures count against the policy that suffered them.

## Results

**HumanEval+ (164):**

| Policy | pass@1 |
|---|---|
| LinUCB bandit (cold start) | 0.744 (122/164) |
| round-robin (derived) | 0.771 |
| static qwen3.5 | 0.768 (126/164) |
| static granite | 0.774 (127/164) |
| **oracle per-prompt router** | **0.890 (146/164)** |

**50-bank (same-day cross):**

| Policy | pass@1 |
|---|---|
| LinUCB bandit (cold start) | 0.920 (46/50) |
| round-robin (derived) | 0.940 |
| static qwen3.5 | 0.960 |
| static granite | 0.920 |
| **oracle** | **0.980** |

The bandit never beat round-robin on either bank (differences within noise at
these n). On the 38 HumanEval+ prompts where exactly one arm passes, it picked
the passing arm 16/38 = 42% — a coin flip. No learning curve (first/second half
identical at 0.744).

## The diagnosis is the finding

The decisions DB shows why, unambiguously: **the reward's success term
saturated.** Bandit-run `AVG(success)` = 1.000 (granite) / 0.987 (qwen) — the
serving-path success signal is the execution gate's "ran without crashing"
verdict, and HumanEval-style code essentially always runs. True hidden-test
pass@1 for the same outputs: 0.774 / 0.768. With success flat, the only
gradient left in the composite reward was **latency** (granite 10.3s vs qwen
18.0s mean), and the bandit correctly drifted to the faster arm on both banks
(87/76 picks on 164; 27/23 on 50 — where qwen was the *better* arm, 0.96 vs
0.92). **The learner optimized exactly what it was given. The ruler saturated —
Era 10's lesson reproduced one level up, with receipts.** LinUCB is bounded by
reward fidelity, not by its own convergence.

## Three structural findings worth more than a manufactured win

1. **The oracle gap is large and real:** 0.774 → 0.890 on HumanEval+ (arms
   complementary: 19 prompts only qwen solves, 20 only granite). Surface
   features can't see it — the 9-dim context is lexical (word count, keyword
   density, tier) and the bandit's 42% on discriminating prompts proves it.
   This is the quantified, committed motivation for **semantic routing**
   (`docs/specs/semantic-routing.md`): the remaining ~12 points live in
   content, not surface stats.
2. **Static rankings rot.** Phase 4 (2026-07-26, same 50-bank): granite 0.900 >
   qwen 0.818. Today: qwen 0.960 > granite 0.920 — flipped, both improved
   (models were re-pulled after the disk-vanish; versions likely moved). A
   static assignment chosen from last month's bench is today's second-best arm.
   That's the honest argument *for* online routing — but it only cashes out
   with a correctness-faithful reward.
3. **Reward fidelity is the next lever, and the cascade already built it.** The
   free local judge (and the code-mode generated-test judge queued from Era 19)
   is exactly a correctness signal the reward could consume where hidden tests
   don't exist in production.

## Mechanics that held up (for reuse)

Isolated-HOME protocol worked end-to-end: pre-create `$HOME/.mahoraga-v2`
(Store.connect doesn't mkdir), server per policy on its own port, seeds pinned
(`MAHORAGA_BANDIT_SEED=1337`, `MAHORAGA_PROMPT_SEED=7`), production state
untouched throughout. Cross top-up after a mid-run kill recovered 109 completed
generations from the scratch DB by joining `tasks.goal` to bank prompts —
nothing re-inferred. HumanEval/129 makes qwen time out reproducibly (2/2);
counted as a real failure. Artifacts: `experiments/p1_cross_granite.jsonl`,
`p1_cross_qwen_topup.jsonl`, `p1_bandit_humaneval.jsonl`,
`p1_cross_50bank.jsonl`, `p1_bandit_50bank.jsonl`.
