# 2026-10-13: one command from a repo to an answer by morning

Item 4 on the list Kaito approved on 10-13. Until now a first-time user had to chain five
commands in the right order (mine, doctor, queue add, service install, report) and know
which failures mattered before bed. `mahoraga audit tonight [REPO]` does that chain.

## What it does

1. Mines up to 25 tasks if the bench has none, and says why commits were dropped when
   none survive.
2. Runs the machine preflight and the isolation canary. A check now carries `waits`:
   power and speed are conditions of the moment that the worker waits out, so being on
   battery at 17:00 doesn't stop a night that runs on AC. A missing agent, a stopped
   Ollama, an unpulled model or a leaking sandbox does stop it, with the fix printed.
3. Estimates the nights the work takes over the window's real length (11 h for
   21:00–08:00, where the doctor had assumed 8).
4. Queues the job with digests pinned, unless the same pending job exists, so running
   it twice queues one night.
5. Starts the launchd worker, installing it if needed. An existing install keeps its
   own workdir and env, which matters on the Studio.

When the window closes on a `tonight` job, or the job ends, the worker writes
`morning.txt` next to the bench (the report, the queue's reason, the verdict command)
and posts a notification with the resolved counts. Other jobs don't, so the Studio's
follow jobs stay quiet.

## Choices

- The default arm is `aider:qwen3.5:latest`, the one the README pulls and the 16 GB
  probe measured, at a 131k context since 10-14 (the night that showed the context,
  not the model, was most of qwen3.6's lead). On 48 GB or more it prints the qwen3.6
  result as a hint rather than guessing a tag: the Studio's `qwen3.6:35b-a3b-coding` is a local build, not a library
  name a user can pull.
- The default condition is blind, matching every published claim. The printed verdict
  command passes `--cond blind`, since `verdict` defaults to feedback and would find no
  evidence.
- The verdict needs two things no run can measure: tasks a month and how you pay. The
  first cut left them out of the morning file, which meant the morning ended on a command
  with two blanks. Now `tonight` asks once (flags, or a prompt in a terminal, blank to
  skip) and saves them to `usage.json` under the bench root. The morning file then
  carries the verdict for each arm and condition, and the notification ends on the call
  ("resolved 9 of 25, STAY, not yet decided"). `verdict` reads the same file, so its
  flags became overrides. The file stays on the machine; nothing in this path sends it.
- Usage is per user, not per job or bench: it describes how you work, and one answer
  should cover every repo you bench. That's why it lives at the root, not on the job.
- A job queued with `--cond both` had an empty notification summary (it filtered on
  `cond == "both"`). The morning file now expands it to both conditions.
